# Collaborative Experiment Agents

실험 agent를 구성할 때, 다음 단계의 실행 권한을 산출물의 검증 결과에 연결한다. 역할 수를 늘리는 것보다 주장을 기각하거나 실험을 중단할 수 있는 판단 경계를 먼저 설계한다.

**근거 구분:** 아래 역할·문서 전달·비판·예측 잠금은 논문의 메커니즘을 재구성했다(§§1–5, 7.1–7.9). 명시적 예산, 공통 인계 필드, 미래 도메인의 진행/수정/중단 게이트는 **스킬 작성자의 구현 관례**이며 원래 프롬프트나 검증된 범용 설계가 아니다. NV 재현, 정량 근거 또는 통계 규칙이 필요할 때만 [논문 근거](references/paper-evidence.md)를 읽는다. 그 수치를 다른 장치에 그대로 적용하지 않는다.

## 역할과 문맥을 배정한다

논문의 실제 배분(§7.2)을 기본으로 삼되, 변경한 배분은 별도로 기록한다. 모든 호출이 새 문맥이라고 가정하지 않는다.

| 역할 | 입력·문맥 | 책임과 출력 |
| --- | --- | --- |
| 독립 제안자 | 장치 요약, 연구 과제, 제외 메커니즘; 다른 제안은 보지 않음 | 주장, 이론적 접근, 실험 가능한 핵심 예측, 불확실성 |
| 배치 평가 PI | 제안 배치마다 새 대화 | 신규성·논리·의의·이론 가능성·검증 가능성 평가; 전부 기각 가능 |
| 선택 후 PI | 선택한 배치의 PI 대화를 계속 유지 | 이론·원고·계산 시험 명세 개발, 과학적 구분력과 판정 책임 |
| 계산 연구자 | 원고 소스와 시험 명세; 작업 디렉터리 유지 | 독립 재구성·계산 검증, 실패 사례, 수정 원고 |
| 별도 실행가능성 심사자 | 원고와 전체 장치 명세; 앞선 PI 대화 제외 | 핵심 예측을 실제 장치로 시험할 수 있는지 평가 |
| 실험자 | 프로토콜·작업 지시; 로컬 메모·로그 유지 | 장치 코드·취득·실험 보고서; 원시 광자 계수는 장치 컴퓨터에 보관 |
| 관리자 | 역할 간 문서 전달과 기각 기록 | 요청 라우팅, 반복 실패 메커니즘 분석, 재설계 조정 |
| 최종 독립 심사자 | 새 대화에서 원고만 받음 | 심사 보고서·권고·확신도; 코드나 원자료 감사로 주장하지 않음 |
| 안전 agent와 사람 | 사람이 설정·확인한 장치 운용 한계 | 실험 전 안전 승인; 사람은 장치 구축과 한계 설정 담당 |

논문에서 PI와 계산 연구자는 실험 보고서로 측정을 평가했다. 원시 계수에 직접 접근해 재검증했다고 쓰지 않는다. 독립성은 역할 이름이 아니라 실제 전달한 정보와 보존한 상태로 설명한다.

## 실행 절차

1. **시작 조건을 정한다.** 장치 능력, 사람이 정한 운용 한계, 접근 권한, 과학적 질문을 문서화한다. 구현 관례로 제안 배치·수정·계산·취득의 시간/비용/횟수 예산과 담당자를 정한다. 권한·안전 조건이 없거나 예산이 소진되면 실행을 멈추고 부족한 조건을 인계한다.
2. **후보를 독립 생성하고 기각한다.** 제안마다 반증 가능한 예측과 실패할 가정을 요구한다. 중심 메커니즘으로 중복을 묶고, 문헌상 신규성과 장치 검증 가능성을 평가한다. 최고점이라는 이유만으로 통과시키지 않는다. 전부 부적합하면 기각 이유를 기록한다. 관리자는 반복 기각된 메커니즘과 결정적 반론을 다음 지시에 반영한다. 수정자는 그 반론을 해소하거나 메커니즘을 바꾼다. 실행 가능한 후보가 없고 남은 예산으로 새 탐색도 불가능하면 ‘선정 없음’으로 종료한다(§§2, 7.3).
3. **주장과 가정을 따로 검증한다.** PI는 정리·가정·미증명 의무를 원고에 구분한다. 계산 연구자에게 원고와 별도 시험 명세를 전달해 결과를 독립 재구성하게 한다. 이상 가정의 위반을 시험하되, 유한 계산 시험을 전체 정리의 증명이나 물리적 실증으로 대체하지 않는다. 불일치는 원고 수정 또는 추가 시험으로 돌린다(§§3, 7.4–7.5).
4. **경쟁 설명을 구분하는 실험을 만든다.** 핵심 이론과 반증 가능한 대안들의 서로 다른 예측을 나란히 적는다. 보류 표적이 평범한 보간으로도 결정된다면 설계를 기각한다. 별도 심사자는 장치·시간상 실행 가능성을, PI는 대안 간 구분력을 검토한다. 안전 승인을 받은 프로토콜·데이터 형식·분석 코드를 실험자에게 전달한다(§§4, 7.6).
5. **규칙 고정과 수치 잠금을 구분한다.** 취득 전에 예측 함수, 표적, 허용오차, 대조군, 분산 유효성, 지지/반증/판정불가 기준을 고정한다. 보정 데이터와 공분산만으로 수치 예측·대안 예측·물리 모형 적합을 계산하고, 표적 분석 전에 잠금 및 해시를 남긴다. 논문의 최종 실행은 취득 후, 표적 평균 계산 전에 수치 잠금을 했다(§7.6). 잠금 시점과 표적 접근 여부를 기록하고 사전 예측으로 과장하지 않는다.
6. **유효성을 먼저 판정한다.** 대조군과 분산 유효성은 지지와 반증 모두의 선행 조건이다. 실패하면 예측이 맞거나 어긋나도 판정불가다. 유효한 경우에만 사전 고정한 지지 또는 반증 규칙을 적용하고, 어느 쪽도 충족하지 않으면 판정불가로 남긴다. 다른 도메인에서는 이 구조를 차용하되 적합한 통계 기준을 취득 전에 정한다(원래 NV 규칙: §7.9 및 참고문서).
7. **실패 원인을 고치고 새 실행으로 시험한다.** 드리프트·순서 효과·진단 오류를 조사한다. 파일럿은 취득 개발로 표시하고 허용 기준을 완화하지 않는다. 정의되지 않은 진단 오차는 성공으로 처리하지 말고 계산을 고쳐 **같은 진단 데이터에 같은 cutoff**를 적용한다(§7.8). 새 프로토콜의 취득은 새 run ID로 구분한다(구현 관례). 이전 실패/판정불가 실행은 이름을 바꾸어 성공으로 만들지 않는다. 잠금된 기준 자체를 바꿔야 하면 별도 연구 계획으로 명시하고 기존 판정을 보존한다.
8. **주장 범위를 제한해 독립 심사를 받는다.** 원고만 전달하는 새 심사 문맥을 만든다. 수학적 보장, 유한 계산 검증, 실제 표적 측정, 해석을 분리한다. 심사자가 보지 못한 원자료나 코드를 검증했다고 보고하지 않는다. 반론은 담당자와 구체적 수정 항목으로 돌리고, 최종 인계에 해결 여부를 남긴다(§7.2).

## 인계와 진행 게이트 — 구현 관례

각 전달 문서에는 `artifact_id/version`, `run_id`(해당 시), 발신/수신 역할, 실제 제공한 입력·접근 범위, 주장과 가정, 시험·대안, 결과와 근거 위치, 미해결 의무, **판정·이유**, 번호가 있는 변경 요청, 다음 담당자와 구체적 작업을 적는다. 취득/분석 인계에는 프로토콜 버전, 규칙 고정 시점, 예측 잠금 시점·해시, 원자료 보관 위치, 유효성 결과, 과학적 분류도 포함한다. 논문이 이 스키마를 사용했다는 뜻은 아니다.

각 결정점은 `진행 / 수정 / 중단`으로 끝낸다. 필수 검증 통과 시 진행, 해결 가능한 결함과 남은 예산이 있으면 수정, 안전 위반·시험 불가능·후보 없음·예산 소진이면 중단한다. 이 운영 게이트는 실험 결과의 `지지 / 반증 / 판정불가`와 별개다. 중단 시 성공 결과를 채워 넣지 말고 현재 산출물, 실패 이유와 재개에 필요한 조건을 반환한다.

## 출처와 적용 한계

El Mustapha Mansouri, Eikichi Kimura, Masato Koga, Keigo Arai, *Collaborative AI agents for autonomous experimental research with solid-state quantum spins*, [arXiv:2610.40589v1](https://arxiv.org/abs/2610.40589v1). 논문은 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)이며 이 스킬은 그 내용을 한국어로 요약·각색하고 명시한 구현 관례를 추가했다. Auctopus 코드의 MIT 라이선스를 논문에 적용하지 않는다.

실증은 특정 NV 표적과 대안에 한정된다. 소형·로컬 모델의 적합성이나 이 역할 구조의 인과적 우월성은 논문에서 검증되지 않았다(논문 범위에 대한 해석). 원래 프롬프트, 완전한 유도·전달행렬 원소 및 원시 분석 자료의 공개 한계는 참고문서에서 확인하고, 빠진 내용을 복원한 것처럼 만들지 않는다.
