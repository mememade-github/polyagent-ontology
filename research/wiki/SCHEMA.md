# SCHEMA: 이 위키의 규약

일반 문서를 로컬 LLM(컨텍스트 10k 미만, 약한 추론)으로 온톨로지화할 수 있는지 조사하는 작업에서, 세 참조 시스템의 as-is만 기록한다. 패턴은 `.claude/skills/llm-wiki/SKILL.md`를 따른다.

## 3계층

| 계층 | 위치 | 규칙 |
|---|---|---|
| Raw | `../findings.md`, `../evidence/` | 공개 가능한 형태로 정제한 뒤 불변. 읽기만 한다. 아래 "저장소에 없는 Raw" 참조 |
| 휘발성 Raw | 스크래치패드 `upstream/`, `paper/p.txt` | 인용 대조에만 읽는다 |
| Wiki | 이 디렉터리 | LLM이 유지한다 |
| Schema | 이 파일 | 저장소의 CLAUDE.md, AGENTS.md는 건드리지 않는다 |

## 저장소에 없는 Raw

이 위키는 프로젝트 안의 독립 연구 공간이다. Raw 중 재배포 판단이 끝나지 않은 자료는 저장소에 넣지 않았다: 바이너리 디컴파일 출력과 주소 목록(`rea/decompiled/`, `rea/ghidra/`), 캡처한 시스템 프롬프트와 요청 로그(`rea/approval/sys.txt`, `rea/approval/c1.log.jsonl`, `rea/adjudicate/a.log.adj`), helix-foundry 샘플 `backend/sample/acme.json`에서 온 온톨로지와 매핑 TOML, 바이너리 분석 JSON(`rea/rust-*.json`), 업스트림 코드 복사본(`ragflow/validator_copy.go`).

- 이 파일들을 가리키는 `E:` 인용과 `[디컴파일]` 행은 **기록만**으로 읽는다. 이 저장소만으로는 대조할 수 없다.
- `sources/`의 해당 행은 `(저장소 미포함)`이다. 나머지 해시는 정제 후 파일 기준이다.
- 정제로 내부 IP, 로컬 경로, 세션 식별자를 `__INTERNAL_IP__`, `__SCRATCH__`, `__RESEARCH__` 같은 표시로 바꿨다. 모델 출력이 되풀이한 프롬프트 예시 문구는 `__PROMPT_EXAMPLE__`로 바꿨다. 그래서 `evidence/`의 스크립트는 실행 기록이며 그대로 실행되지 않는다.
- 위키의 "있다", "보존", "스크래치패드", "이 세션", "코디네이터", "조정자"는 2026-11-06 수집 당시를 가리킨다. 당시의 세션 기록은 저장소에 없다. "기록만"은 이 경우 results.md나 위키의 판독만 남았다는 뜻도 포함한다.
- 논문 인용의 `p.txt` 행 번호는 수집 당시 사본 기준이다. 저장소만으로는 절 번호까지 대조할 수 있다.
- 업스트림 클론과 논문 텍스트는 포함하지 않는다. 대상 버전은 [method-and-limits](method-and-limits.md)의 커밋이며, `AO:`, `HF:`, `RF:` 인용은 그 커밋을 받아 대조한다.

## 금지

- 향후 계획, 권고, 구현 선택을 쓰지 않는다.
- 임의 판단을 쓰지 않는다. 시스템 간 우열을 매기지 않는다.
- 미지를 추론으로 메우지 않는다.
- 소스 불일치에서 한쪽을 조용히 고르지 않는다. `contradictions.md`와 영향 페이지에 기록한다.

## 등급

| 표기 | 뜻 | 증명하는 것 | 증명하지 않는 것 |
|---|---|---|---|
| `[실행/Stub]` | 실제 코드나 바이너리를 Stub 모델로 돌려 관찰 | 코드 동작, 전송 내용, 응답 처리 | 모델 품질, 저성능 모델의 수행 능력 |
| `[실행/실모델]` | 실제 로컬 모델(`qwen2.5:3b`, Ollama 0.40.10, CPU)로 실행 | 그 입력에서 그 모델이 낸 출력과 코드의 처리 | 일반적 품질, 다른 모델·하드웨어. 표본이 작아 평가 수치로 쓰지 않는다 |
| `[실행]` | 모델 없이 실행 또는 저장소 상태 조회 | 그 실행의 결과 | 파이프라인 전체 |
| `[코드]` | 소스만 읽음 | 그 위치에 그 코드가 있음 | 실행 시 동작 |
| `[논문]` | 저자의 진술 | 저자가 그렇게 썼음 | 재현, 코드 일치 |
| `[심볼]` | 바이너리 심볼 표와 문자열 | 그 이름이 있음 | 함수 내부 동작 |
| `[디컴파일]` | Ghidra 의사코드를 읽은 해석. 이름 없는 변수를 해석했으므로 `[실행]`보다 약하다(R:7) | 그 의사코드가 그렇게 읽힘 | 실행 시 동작의 확정 |
| `[바이너리]` | 바이너리에서 값을 직접 읽음(R:8) | 그 위치의 값 | 그 값의 사용 방식 |
| `[미입증]` | 직접 근거 없음 또는 규칙·해석 진술 | 없음 | 해당 주장 |

사용자가 정한 등급은 `[실행]`, `[코드]`, `[논문]`이다. `[실행/Stub]`은 `[실행]`에 Stub 조건을 붙인 표기이고, `[심볼]`과 `[미입증]`은 함수 이름 근거와 근거 부재를 구분하려고 더한 표기이다.

`[디컴파일]`은 해석이므로 `[실행]`과 어긋나면 `[실행]`을 앞에 두고 어긋남을 기록한다. `[바이너리]`는 원시 덤프가 evidence/에 없으면 "기록만"을 함께 쓴다.

"기록만"은 원시 출력이 evidence/에 없고 findings.md 또는 interim.md의 서술만 있다는 뜻이다. 등급은 원 기록의 등급을 따른다.

## 인용 표기

| 접두 | 위치 |
|---|---|
| `F:n` | `findings.md` n행 |
| `I:n` | `evidence/rea/interim.md` n행 |
| `E:경로` | `evidence/경로` |
| `AO:경로:n` | auto-ontology 클론 `c4495670` |
| `HF:경로:n` | helix-foundry 클론 `c7de4051` |
| `RF:경로:n` | ragflow 클론 `2096707f` |
| `R:n` | `evidence/rea/results.md` n행 |
| `P:§x (p.txt:n)` | 논문 절과 `paper/p.txt` 행 |

행 번호는 수집 시점 파일 기준이다. `sources/` 페이지에 해시가 있다.

## 페이지 형식

요소마다 한 행을 두고 ID, 요소, 등급, 인용, 관찰, 미입증 칸을 채운다. 각 요소의 홈 행은 하나이고, 다른 페이지는 링크한다. 근거가 없는 요소도 `[미입증]`으로 남긴다. `coverage.md`는 findings.md와 interim.md의 내용 행을 요소에 대응시킨다.

## 대체 표기

앞선 진술은 지우지 않는다. 대체된 문구는 `~~원문~~ → 새 내용(요소 ID)`으로 남기고, 덧붙인 내용은 `**results.md 갱신:**`으로 시작한다. `contradictions.md`의 `갱신` 줄과 `log.md`에도 기록한다.

## 운영

- **Ingest**: 소스를 하나씩 읽고, `sources/`에 요약과 해시를 두고, 요소 행과 대조 기록과 `index.md`를 갱신하고, `log.md`에 `## [YYYY-MM-DD] ingest | 제목`을 추가한다.
- **Query**: `index.md`에서 시작한다. 재사용할 답은 페이지로 남긴다.
- **Lint**: 깨진 링크, 고아 페이지, 내부 ID 미해결, 대응 없는 원문 행, 금지 표현, 소스 해시 변경을 검사하고 `## [YYYY-MM-DD] lint | 제목`으로 기록한다.
- ~~**인용 대조 갱신**: `concepts/quote-validation.md`의 QV-P1은 새 raw 소스 수집 시 갱신한다.~~ → results.md로 수집했다. 임계값 값과 정규화 내용의 raw가 들어오면 QV-20, QV-23을 갱신한다.
