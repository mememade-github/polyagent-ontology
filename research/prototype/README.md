# Memoryless mixed-source ontology prototype

This runnable experiment combines code-derived source structure with small, independent, schema-constrained local questions. It targets weak local models such as `qwen2.5:3b`. It makes no reproduction or novelty claim and contains no target ontology or corpus-specific inference vocabulary. `build_acme.py` is a fixture-format adapter only; its table selections are not used by the inference code.

The design motivations supplied to this implementation are Memoryless CQbyCQ (isolated questions), EDC (extract before canonicalizing), LOM (combine schema and value overlap), and AutoSchemaKG (induce event/statement concepts). These are motivations, not verified implementations of those papers. This role did not retrieve or verify paper full texts; the parent maintains the paper-access ledger and frozen evaluation outside this prototype. Inference does not read reference answers or gold labels; the documentation role inspected only sanitized evaluation metadata and reference names/hashes. Gold was previously a known regression test, not a blind test; Acme is development input. The frozen metrics protocol is unchanged.

## Run

Use Python 3 and a running Ollama server with the model already installed. No dependency install or model pull is performed.

```bash
export OLLAMA=http://localhost:11434
export MODEL=qwen2.5:3b
export CORPUS=/path/to/corpus
export PRIVATE_RUN=/tmp/ontology-run-unique-name
export MEASUREMENTS=/path/to/new-measurements.json
python3 prototype/onto.py "$CORPUS" "$PRIVATE_RUN" --measurements "$MEASUREMENTS"
```

Run from the directory containing `prototype/`, or adjust that relative path. The private output must be a new directory outside the repository under `/tmp`; measurements must also be a new file. Existing directories/caches are refused. There are no retries or resumed runs. Below 2 GB free space on `/workspaces`, startup and each generation fail. Failed runs retain a failure report where initialization completed; exceptions produce a nonzero exit.

Optional fixture conversion, also into a new private directory:

```bash
export HELIX_CLONE=/path/to/helix-checkout
export MIXED_CORPUS=/tmp/mixed-corpus-unique-name
python3 prototype/build_acme.py "$HELIX_CLONE" "$MIXED_CORPUS"
```

The builder validates sources before creating output, accepts only CREATE TABLE and INSERT statements, and executes them in memory with an SQLite authorizer. It never deletes output, drops tables, attaches databases, or enables extension loading. It writes selected tables to a new SQLite file, JSONL, escaped key/value logs, and copies Markdown documents. It rejects other SQL dialect constructs rather than silently discarding them.

## Method and evidence

SQLite declared keys, including composite keys and numeric foreign keys, are preserved. Non-DB records retain physical row identities and expose minimal observed candidate keys separately from declared primary keys: all cells must be non-null scalar values and unique across observed rows, with at least one id/key/code-like column. Composite candidates are supported. Observed uniqueness is not a future uniqueness guarantee; arbitrary unique prose alone never establishes a key. Independently namespaced type identifiers prevent normalized names or repeated source table names from overwriting each other. Nondeclared link candidates require type-compatible values with at least 0.95 distinct-value overlap against declared or observed candidate keys, without requiring matching column names. Key-to-key coincidences are excluded. Composite overlap and declared composite foreign keys are supported. Candidates retain inferred status, key basis, overlap, distinct support/denominator and row counts; overlap is not semantic confidence. Declared direct foreign keys remain even when a transitive path exists.

JSONL objects retain nested values and arrays; scalar/array records are wrapped under `value`. Logs retain every nonblank line and parsed fields, with physical line identities. Markdown, text and reStructuredText files are discovered recursively, without a required `docs/` folder. Other binary/document formats are unsupported. SQLite tables, log templates and JSONL collections provide initial types. Source folders provide discovery/context, not automatically invented semantic types.

Each document sentence receives one extraction question using the exact simplified diagnostic prompt and four-field schema (subject, relation, object, concept). Section context remains in stored evidence. Code attaches the full source sentence as quote; the model does not regenerate it. A separate memoryless genre question uses relative folder/path, first heading and an opening sample bounded to 768 UTF-8 bytes, without splitting a character. Per-document sampled/omitted byte counts are private in `documents.json`, with aggregate counts in measurements. Repeated genres with anchored mentions can induce hybrid document types; folder/path supplies classification context. Claims retain full-sentence evidence, exact subject/relation/object spans and a generic event/statement concept. A separate isolated verification question checks roles, attribution, negation, conditions and modality. Original sentences and rejected claims stay in private evidence. Repeated concepts across documents are canonicalized after extraction. Verification by the same weak model is not an independent truth oracle; semantic precision still needs the parent's source proposition audit.

Categorical-column questions use a declared conservative eligibility rule (small repeated string domain also appearing in documents). This intentionally limits recall; numeric, high-cardinality and unmentioned categories are not promoted. Entire oversized extraction units, verification claims and eligible column questions are excluded explicitly rather than truncated. Every unit with no accepted fact, any rejected claim, or a saturated one-item result (any returned item, even if rejected) is recorded in `uncovered.json`; this does not prove complete proposition coverage for accepted units. Extraction returns at most one proposition per sentence, trading recall for a smaller output task; every returned item marks capacity_reached. Long sentences are not split into potentially misleading fragments.

## Bounds, failures and publication

All final runs use the same fixed explicit `num_thread=8` configuration. A local neutral-prompt probe measured evaluation durations of 2.458s, 0.907s and 0.697s for 16 decoded tokens at 1, 4 and 8 threads respectively. Eight threads is a measured local configuration, not a universal optimum; the data and metrics protocol remain fixed.

The prompt guard counts UTF-8 bytes of serialized messages **and JSON schema**, plus 512 tokens reserved for chat framing, requiring a bound strictly below 3,800. This assumes a byte-level tokenizer and framing within that reserve for the selected model. `num_ctx=8192`, temperature zero, seed seven and per-call output budgets are explicit. Actual prompt/output token counts, message characters/UTF-8 bytes, serialized message-plus-schema characters/bytes, termination, per-call wall/client CPU durations, run wall/client CPU durations, configuration and model digest are recorded. Client CPU excludes server/model CPU. Extraction permits at most one item with a 600-token completion budget within the 8,192-token context; incomplete generations still fail explicitly. The prompt simplification was tuned on the first three Summary sentences of the first Acme document. With 256 output tokens those three diagnostics terminated in 0.42–2.23 seconds with valid JSON: the first invented relation/object spans, the second returned literal supported spans, and the third abstained. This establishes termination improvement on three examples only, not extraction quality. The 600-token budget allows more capacity for longer sentences and was used for the completed measured repeats. The prior three-item/2,400-token candidate failed on gold1 call 4 and Acme call 10 with done_reason=length; neither produced a completed ontology. Ollama exposes no independent untruncated prompt count; counters alone cannot prove absence of server-side truncation or validate the framing reserve for arbitrary models. Use the configured model and inspect its measured counters before drawing conclusions.

Malformed JSON, wrong schema shape, missing required fields, incomplete generations, missing prompt counts, transport errors and unsupported declared foreign keys fail visibly. Legitimate empty extraction is distinct from execution failure. A run with no usable rows/facts or with documents but no grounded document facts fails. Progress for each actual generation contains metadata only. Raw HTTP response bodies are saved in private raw_calls before JSON parsing, termination checks or schema validation, retaining failed generations for diagnosis. Reports include error_type and an allowlisted safe error_message without source content or paths. No automatic retry or cache reuse can hide failed calls.

`$PRIVATE_RUN` is **private**: ontology, raw request/response evidence, tables, row identities, facts, exclusions and uncovered sentences may contain source payload. Keep it outside the repository. Only the explicitly requested measurements file is intended for publication. It contains counts, provenance totals, input/code SHA-256 hashes, model/configuration and per-call token/timing/status metadata; no source sentences, field names, row identifiers or paths. Hashes enable comparison but do not anonymize low-entropy inputs. Never publish the private directory as a measurements artifact.

Every emitted type/link has provenance: `code` means wholly model-independent, while `hybrid` includes any LLM dependency (including links induced from model concepts or categorical decisions). Raw evidence is retained for evaluator inspection. The report hashes source files and implementation; preserve the invocation, Python/Ollama versions and external corpus revision in the parent's rebuild ledger. Absolute private source locations contribute to internal identity, so moving a corpus changes internal identifiers.

The coordinator completed two fresh Acme runs and two known synthetic gold regression runs after final code freeze. Acme was inspected development input and its first three Summary sentences informed extraction prompt redesign; this was live development tuning, not a blind evaluation. Both Acme runs emitted 10 types, 13 links and 3 facts; both gold runs failed with zero ontology types. See [measured results](../evidence/prototype/results.md) for full denominators, audited fact quality, prior failed attempts, and the frozen column-name assumption defect. Independent publication review and final repository checks remain with the parent.

The neutral integer probe also tested 16 threads (37.714429s evaluation duration for 16 tokens), then rechecked 8 (0.716987s). Default-thread development was aborted after two completed calls. The prior 2,400-token implementation failed gold call 4 and Acme call 10 with length termination; these failures remain in the public development metadata. Final execution used Python 3.10.12, Ollama 0.40.10 CPU, actual model size 3.1B Q4_K_M, temperature 0, seed 7, context 8192 and 8 threads. No new model pull was used.

Publication includes code and measured metadata, with protocol/input/code/reference hashes and Apache-2.0 HelixDB/helix-foundry attribution. Existing public synthetic `evidence/real-model/gold.md` and `gold.txt` remain; new raw model outputs and source samples remain private. JSONL export is not a live NoSQL connector; nested arrays are retained rather than normalized, freeform logs lack semantic parsing, folder paths aid classification without a folder hierarchy ontology, and OWL/SHACL/rules and cross-sentence contextual reasoning are absent. Stable repeated output does not establish correctness.
